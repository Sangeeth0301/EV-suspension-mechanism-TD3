## 🔍 The Problem (Why This Project Exists)

Modern EVs are placing motors directly inside the wheel hub (**In-Wheel Motors / IWM**). This creates **three simultaneous engineering crises** that no single paper has solved together:

| # | Problem | Impact |
|---|---|---|
| 1 | **Heavy Wheel Bounce** — IWM increases unsprung mass by 30–50%. Fixed-gain controllers cannot adapt from smooth highway to broken road. | Passenger discomfort, reduced tyre grip |
| 2 | **CAN-Bus Cyber Vulnerability** — The suspension ECU runs over an unauthenticated network. A DoS flood or False Data Injection at highway speed can crash the car. | Life-safety threat |
| 3 | **Battery Drain** — Every bump the actuator fights costs battery energy. No controller intelligently decides when to fight vs. when to harvest that energy back. | Reduced EV range |

---

## ✨ What We Built (The 2 Core Novelties)

### Novelty 1 — The Road-Adaptive Brain (UKF + LPV H∞)
The base paper uses one fixed controller for all road conditions. Ours uses a real **Unscented Kalman Filter (UKF)** that continuously estimates:
- `ρ(t)` — *How rough is the road right now?*
- `ρ̇(t)` — *How fast is it getting worse?* ← **No existing paper uses this**

The `ρ̇` rate signal is fed into an **LPV H∞ controller** with CARE-equation derived gains. The controller pre-stiffens the suspension *before* the pothole fully hits — like an early warning radar.
**Result:** RMS body acceleration drops from **0.62 m/s²** (base paper) → **~0.32 m/s²** (ours)

### Novelty 2 — The Energy Harvester (TD3 Deep Reinforcement Learning)
The base paper wastes 100% of bump energy as heat. We replace the hardcoded if-statement supervisor with a real **TD3 (Twin-Delayed DDPG) agent** that:
- Reads battery SoC, `ρ(t)`, and `ρ̇(t)` every millisecond
- Uses a **dynamic multi-objective reward** that weighs comfort vs. harvest based on road urgency
**Result:** **22–28%** of bump kinetic energy harvested back into the battery

## 🚀 How to Run Locally

This project consists of two parts: a **Python Simulation Core** (Backend) and a **React Dashboard** (Frontend). You can run them locally by following these steps.

### Step 1: Clone the Repository
```bash
git clone https://github.com/YOUR-USERNAME/EV-suspension-mechanism-TD3.git
cd EV-suspension-mechanism-TD3
```

### Step 2: Run the Python Simulation Core (Backend)
This script calculates the physics, runs the AI, and exports the data for the dashboard.
```bash
# Install the required Python packages
pip install -r requirements.txt

# Run the simulation (Takes ~5-10 seconds)
python Simulation_Core/run_simulation.py
```
> **Note:** Upon completion, the script generates a performance table in the terminal, exports `simulation_data.csv` to the results folder, and renders a static matplotlib 5-panel graph (`Phase5_Upgraded_Results.png`).

### Step 3: Run the React Dashboard (Frontend)
The interactive web dashboard visualizes the simulation results generated by the backend.
```bash
# Navigate to the dashboard directory
cd Simulation_Dashboard

# Install the Node dependencies
npm install

# Start the Vite development server
npm run dev
```
> **Access the Dashboard:** Once the server starts, open your browser and go to `http://localhost:5173/`. You can hit **PLAY** to watch the real-time simulation kinematics and KPI updates!
